# Контент по делу — MVP согласования

Python 3.12+, без сторонних зависимостей. SQLite хранит очередь и смещение long polling. Это первая версия издателя: автоматический сбор и генерация пока не подключены. Учебные примеры в семи стартовых материалах не выдаются за реальные ответы моделей.

## Локальная проверка

Из `/workspace/TG`:

```sh
python -m unittest discover -s tests -v
python app.py seed
python app.py status
```

Повторный `seed` не дублирует материалы и не перезаписывает правки. Файл `.state/publisher.sqlite3` содержит рабочую очередь: сохраняйте его при перезапусках и резервируйте перед изменениями. `.env` автоматически не читается.

## Подключение Telegram

1. Создайте канал и отдельного бота через официальный `@BotFather`.
2. Добавьте бота администратором с правом публикации.
3. В защищённой среде процесса задайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID` (`@username` публичного канала либо числовой ID), `TELEGRAM_REVIEWER_ID` (числовой ID вашего аккаунта).
4. Напишите боту `/start`. При остановленном издателе выполните `python app.py identity` с уже заданным токеном: команда покажет ID отправителей личных сообщений. Выберите свой ID для `TELEGRAM_REVIEWER_ID`. Не вставляйте URL с токеном в браузер, чат или логи. Если сообщений нет, отправьте новое личное сообщение боту и повторите команду.
5. Напишите своему боту `/start`, затем запустите издатель. Нужен исходящий HTTPS к `api.telegram.org`. Токен должен быть реальным значением, доступным процессу; подстановка proxy-секретов требует отдельной проверки совместимости с Telegram URL.

```sh
cd /workspace/TG
mkdir -p .state
flock -n .state/worker.lock python app.py run
```

Один процесс на одну базу. Для постоянно работающего сервера используйте supervisor/systemd или аналогичный менеджер с теми же переменными и рабочим каталогом. Рабочее окружение разработки не обеспечивает постоянную работу.

## Порядок согласования

По умолчанию публикации на паузе. `/next` показывает черновик и отдельную карточку с чек-листом и кнопками. Выполните проверку, внесите правки через `/edit ID` и текст со следующей строки. Команда `/verify ID` подтверждает проверку человеком; она не выполняет её автоматически. Затем отдельно нажмите «Одобрить».

Кнопка «На доработку» только меняет статус. Автоматической переработки нет. После любой правки проверка и одобрение сбрасываются. `/show ID` возвращает карточку, `/status` показывает состояния. Только указанный владелец в личном чате управляет ботом.

После подготовки очереди `/resume` включает публикации: максимум один пост за календарный день в окне 10:00–10:59 Europe/Moscow, по ID. Окно настраивается `PUBLISH_TIMEZONE`, `PUBLISH_HOUR`. Если процесс не работал в это окно, публикация ждёт следующего дня: накопленные посты не отправляются пачкой. `/pause` останавливает новые отправки; уже начатый сетевой запрос отменить нельзя. Изменение часового пояса действующей очереди выполняйте на паузе.

Последовательность недельного набора важна: не одобряйте дайджест до выхода остальных постов. Перед его одобрением вручную добавьте ссылки, создайте отдельный опрос либо уберите обещание опроса.

## Неоднозначная отправка

При сбое в момент отправки пост получает `uncertain`, все дальнейшие публикации блокируются. Автоповтора нет: Telegram sendMessage не даёт ключа идемпотентности. Остановите процесс и проверьте канал:

```sh
# Если пост действительно вышел (подставьте его message_id):
python app.py resolve --id 1 --outcome published --message-id 123
# Если точно НЕ вышел, вернуть на повторное согласование:
python app.py resolve --id 1 --outcome draft
```

Затем запустите процесс. Дневной слот остаётся использованным, повторная публикация возможна со следующего дня. Проверка сбрасывается; для возвращённого черновика нужны `/verify` и одобрение. Не возвращайте пост в draft, если результат отправки неизвестен.

## Что пока не проверено и не реализовано

Реальные API-запросы и публикация требуют токена, канала и reviewer ID. Локальные тесты используют имитацию Telegram. Практическое выполнение промптов в моделях не проведено; у каждого материала есть чек-лист. Все импортируемые посты непроверенные.

Следующий этап: разрешённые RSS/API → отбор → черновики со ссылками → проверка. Затем лимит API-бюджета и аналитика рекламы. Автоматическая генерация, опросы и графическая аватарка сейчас отсутствуют. Источники конкурентов для анализа не являются разрешением на копирование или массовый сбор их публикаций.

## Постоянный запуск

Готовы Dockerfile и compose.yaml. Подробности переноса опубликованных постов, секретов и восстановления: [docs/deployment.md](docs/deployment.md). Не запускайте чистый seed на новом сервере вместо переноса существующей базы: это потеряет историю отправок.

Команда `/queue` показывает последние 20 постов и статусы. Приложение дополнительно блокирует второй процесс с той же базой. Внутренний lock не защищает от запуска одного токена на двух разных серверах: при переносе сначала остановите старый издатель.

Резервная копия: `python app.py backup --output backups/новое-имя.sqlite3`. Копия проверяется на целостность и не перезаписывает существующие файлы. Для контейнера токен читается из файла `TELEGRAM_BOT_TOKEN_FILE`.

Для выбранного запуска на ноутбуке: [docs/laptop.md](docs/laptop.md). Python без сторонних библиотек — основной путь, Docker необязателен. Скрытый ввод токена: `python3 local.py configure`. Не запускайте локальную и облачную копии одного бота одновременно.

Выбранный владельцем вариант — macOS с уже установленным Docker Desktop: [пошаговый запуск](docs/mac-docker.md). VPS откладывается. Перед переносом нужна отдельная передача свежей базы, затем остановка облачного издателя и запуск на Mac без параллельного polling.
