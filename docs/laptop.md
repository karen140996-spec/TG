# Запуск на ноутбуке

VPS пока не нужен. Рекомендуемый первый путь для macOS/Linux — Python 3.12+, без Docker и сторонних библиотек. На Windows используйте WSL2 с Linux либо Docker Desktop; нативный Windows пока не поддерживается (fcntl).

## До переноса

Код должен оказаться в каталоге TG на ноутбуке. Он ещё не опубликован в GitHub: пустой удалённый репозиторий не содержит текущие файлы. Путь /workspace/TG принадлежит облачной среде, а не ноутбуку. Способ передачи согласовывается отдельно; не копируйте токен в чат или Git.

Проверьте в терминале ноутбука:

```sh
python3 --version
```

Нужна версия 3.12 или выше. Если Python не установлен, используйте официальный установщик с python.org; выберите поддерживаемую версию, не отключайте проверки подписей и TLS. Далее перейдите в каталог проекта (команду cd нужно адаптировать к месту сохранения).

## Порядок переноса

1. Код и свежая резервная копия очереди передаются на ноутбук раздельно. Во время финального переноса старый бот должен быть остановлен. До этого он может обслуживать согласование в облаке.
2. В каталоге проекта на ноутбуке:

```sh
python3 -m unittest discover -s tests -v
python3 local.py configure
```

Настройщик предложит канал и ваш ID. Введите токен в скрытом приглашении локального терминала. Токен хранится в `.secrets/telegram_bot_token` с правами 600. Настройки — `.state/runtime.json`. Оба пути исключены из Git. Никаких команд с токеном в строке не требуется.

3. Восстановите свежую копию, полученную из облачной среды:

```sh
python3 local.py restore --file /путь/к/publisher-transfer.sqlite3
python3 local.py status
```

Подставьте реальный путь. Restore не заменяет существующую базу и включает паузу. Пост #1 должен быть `published`. Не выполняйте seed для замены истории действующего канала.

4. Убедившись, что старый издатель остановлен:

```sh
python3 local.py run
```

В личном чате с ботом отправьте `/queue`. Получение списка и сохранение опубликованного поста #1 — первая проверка. Остановите процесс Ctrl+C, снова запустите, повторите `/queue`. Публикации должны оставаться на паузе.

## Работа на macOS без сна

Пока процесс работает в терминале, его можно запустить так:

```sh
caffeinate -i python3 local.py run
```

Это предотвращает простой сон системы во время работы команды, но не гарантирует работу при закрытой крышке. Ноутбук держите подключённым к питанию и интернету, крышку открытой. Закрытие терминала, выключение или перезапуск ноутбука останавливают процесс. После перезапуска запускайте его вручную. Автозапуск launchd добавляется только после проверки расположения проекта на вашем ноутбуке.

Посты отправляются только в настроенном часовом окне (первоначально 10:00–10:59 по Москве). Если ноутбук в это время спит или выключен, публикация ждёт следующего дня. Не включайте `/resume`, пока не готовы к такому режиму и нет проверенных одобренных материалов.

## Резервная копия на ноутбуке

```sh
python3 local.py backup --file backups/publisher-YYYY-MM-DD.sqlite3
```

Используйте новое имя; держите дополнительную копию вне ноутбука. Копия токена для восстановления хранится отдельно в вашем менеджере паролей. Каталог `.state` не удаляйте: там история публикаций.

## Вариант с Docker Desktop

Если Docker Desktop уже есть и запущен, применим compose.yaml и инструкция docs/deployment.md; слово VPS в ней заменяется на ноутбук. Docker Desktop тоже останавливается вместе со сном/выключением ноутбука. Ради текущего небольшого Python-приложения устанавливать Docker необязательно.
